## Question

当前 fork 中所有直接读写 `.codegraph/codegraph.db`（sqlite）的调用点在哪里、各自查什么、迁移到"graph.json + FTS 缓存"链路的语义映射是什么？

背景：codegraph TS 运行时将退役（MAP 已定），直查点必须迁移或重写。盘点范围：

1. `graphify/serve.py`（Phase 4 的 15 个 MCP 工具中哪些直查 db——ranked 通道、structure\_queries 等）
2. `scripts/ranked.py`（FTS5 BM25 通道现在查 codegraph.db 的哪些表/列/SQL）
3. `scripts/rebuild_entry.py`（db\_fingerprint：MAX(files.indexed\_at) + WAL mtime）
4. `scripts/session_snapshot.py` / `scripts/run_analysis.py` / `scripts/adapter.py`（load\_codegraph 的表依赖面：nodes/edges/kind 词表/unresolved\_refs）
5. `tests/` 中依赖 `tests/fixtures/codegraph-fixtures/mini.codegraph.db` 的测试清单
6. 每个直查点的 SQL 依赖（表/列/FTS 虚表/rank 函数）→ 在新链路（graph.json 节点属性 / FTS 缓存）中的等价物是否存在（如 FTS5 bm25 语义、files.indexed\_at 的新等价指纹）

产出：直查点清单表（文件:行、功能、SQL 面、新链路等价物、迁移难度分级）。

### 五、bm25 语义等价性结论

**可等价重建。** `bm25(nodes_fts, 0, 3, 2, 0.2, 1)` 是 SQLite FTS5 的确定性打分函数，只依赖索引语料统计（TF/DF/文档长度）与列权重参数，与虚表由谁构建无关。自建 FTS5 缓存（MAP 决策 2：落盘可重建缓存）只要同 5 列（id/name/qualified\_name/docstring/signature）、同列权重、同默认 tokenizer（unicode61）、同 MATCH 隐式 AND + ORDER BY score，即得**同序同分**结果；`snippet()` 亦为标准函数直接平移。金标 test\_golden\_matrix\_recall\_and\_no\_degrade 的 BM25-only 对照可直接保留为迁移验收闸门。**唯一前提**：docstring/signature 两列现 0 覆盖（MAP 实测基线），须先完成提取层增强（决策 5，Q8=a），否则 doc=0.2/sig=1 两列退化为空列、rank 分布改变（须在 06 票诚实标注）。

### 六、最大迁移难点

`edges.metadata` 的**解析元数据**（resolvedBy ∈ {instance-method, fuzzy, qualified-name} / confidence）——`_edge_dispatch_info`（adapter.py:217 与 serve.py:1846 双副本）据此标 dispatch 候选。该信号是 codegraph TS 解析器解析跨文件引用时的产物，tree-sitter AST 无对应信息：新链路下 JOIN 无表可查、resolvedBy 恒空 → B3 dispatch/fanout 标注与 test\_dispatch\_trace.py:376 金标整体失效，需裁决"保守全标 dispatch\_candidate=true（宁多标）"或"dispatch 通道退役"。次级难点同类：unresolved\_refs（knowledge gaps + ranked gap\_hit 通道）同为 TS 解析器特产，AST 无 failed refs 概念。

### 七、结论

1. 直查面完全收敛于 7 文件 17 SQL 点 + watch 门控/指纹/子进程；无散落暗依赖（graphify/ 包内仅 serve.py 与 watch.py 触及 `.codegraph`）。
2. 易迁移（有直接等价物）：点查/映射类（`_map_nodes`、pinning、git\_symbols 查询、门控、freshness 指纹平移、benchmark）。
3. 中迁移（可重建但需设计）：FTS5 缓存本体（05 票）、db\_fingerprint 新语义、`_map_edges` 去重简化、热区度数单位口径、get\_node 名片的 signature/docstring/end\_line 提取层补齐。
4. 难迁移（语义损失，需 HITL 裁决）：dispatch 解析元数据（双副本 + 金标）、knowledge gaps/gap\_hit 通道、codegraph sync 子进程替换（架构级，联动决策 4 watcher）。
5. session\_snapshot.py 与 10 个纯图工具零迁移；测试面 3 个 fixture 文件 + 2 个 golden 文件（3 用例）+ 8 个 schema 耦合文件待改写。
